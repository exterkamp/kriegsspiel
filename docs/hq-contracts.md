## First-gate signatures and semantics

`contracts.ts` is dependency-free TypeScript with DOM types. It freezes `HqNavigation`, `MapSurface`, read-only `HqDataSource`, `HqRepository`, and an unavailable `ReplaySource` reservation. It contains no order/conference/annotation/replay-frame schemas. The fixture source and future live adapter share the read-only boundary; unavailable features return explicit errors and cannot cause outbound work.

### Shell navigation and selection

- `ViewId` covers table, in-tray, orders, roster, conference, terrain studies, journal and replay. Desk objects and keyboard routes navigate to these views; unfinished views may show a named scaffold and capability reason. Sign, confer, annotate and reveal actions remain disabled.
- `ShellState` contains fixed game/side/player scope, active view and a discriminated unit/paper selection. No mark selection is promised in this first schema. Selection uses IDs, never a Three.js mesh, DOM node, hidden unit record or array index.
- `navigate(view, returnFocusKey, op)` completes after the transition and focus transfer. `returnFocusKey` is an application-owned stable DOM lookup key, not persisted HTML. Returning restores focus to that desk object; missing objects fall back to the active view heading.
- Selection survives desk/table round trips and incoming snapshots while its scoped ID still exists. Missing IDs clear selection; cross-scope selection returns `scope-mismatch`. Navigation does not issue game commands or change source state. Input/textarea/contenteditable and open dialogs suppress global shortcuts.
- Navigation uses latest-request-wins and serializes rollback/transition work. A newer request aborts the earlier transition; only the latest may commit view/focus. An abort restores the prior settled view/camera before proceeding. The superseded promise returns `aborted`; it cannot later commit focus. Reduced motion completes without dolly/fade delay. The coordinator binds navigation to the one persistent MapSurface.

### MapSurface

All map positions and lengths use **metres**, x east/y south, north-west origin. Facing is compass radians, 0 north and clockwise; shape offsets are x right/y front in the unit's frame. No gameplay grid, floor, tile centre or eight-way quantization is allowed in the continuous implementation.

`PublicArtwork` registers the whole image to `[0,widthM] × [0,heightM]`, with positive non-square extents, positive image dimensions, stable identity/revision, credit and licence. Cropped/georeferenced assets need a future explicit transform rather than guessing from pixels. Public artwork contains no terrain costs, passability, concealment, strength, deployment or truth metadata. The map branch's sampling grid is not a client/game coordinate system. Asset paths here are fixture-owned public URLs; no map generator API is assumed.

Metre extents must be finite and strictly positive; pixel dimensions must be positive safe integers, at most 16,384 per axis. Resolve image URLs against the application location: require the same HTTP(S) origin, no credentials, no fragment/auth-bearing query and a normalized path explicitly listed in the coordinator's approved public-asset manifest. Reject `javascript:`, `data:`, `blob:`, off-origin URLs and paths to private APIs, even if same-origin. `sourceUrl` is attribution text/link only, not a texture-fetch target. Asset authorization is not inferred from the URL's spelling.

`MapPresentation.mode='fixture-knowledge-preview'` makes the existing own/contact display explicit. These pieces are fixture knowledge for #49 rendering, not persisted player beliefs or automatically plotted live enemies. D2's live report-to-mark policy remains a later gate; a live map presentation is deliberately not defined here. Fresh/stale display metadata cannot manufacture report dates. Stale wire contacts have no facing/footprint; `appearance=null` draws an explicitly generic ghost, not a claimed enemy formation.

`MapPresentation.snapshot` carries canonical `atGame`, `epoch` and `ordinal` from the HqSnapshot used to build it. Own/fresh tags say “snapshot at …”; stale tags use the supplied observation and age checked against that time. Receipt/render time is never a report date. Within an epoch, reject lower ordinals as `conflict`; equal ordinals require identical source content. A new source epoch requires explicit coordinator session reset, never an implicit late-result takeover.

- Lifecycle: new → mounted → presentation ready → active/inactive → disposed. `mount` accepts one canvas once; a repeated mount returns `conflict`. A failed mount releases partial resources. Before presentation, camera/picking/focus return `not-ready`. `dispose` is idempotent and terminal.
- `apply` validates the complete candidate, loads its art and commits atomically; failure keeps the last valid scene. The coordinator/adapter serializes applications and cancels obsolete async loads, so old completion cannot replace newer content. Equal identity/revision is a no-op; equal revision with different content is `conflict`. A revision is an opaque token, not an ordering key.
- The same artwork identity/revision preserves camera and piece objects when content is unchanged. A different map invalidates bookmarks and fits the new extent once. Changing tags must release replaced textures without leaking materials/geometry.
- `transitionTo('desk', …)` retains the settled table bookmark and dollies/fades. Disable controls during transition, keep RAF rendering until its final frame, then suspend with `setActive(false)`. On return, activate RAF before the table transition and restore the bookmark; controls resume only on the settled table. Reduced motion still renders one final frame before suspension. `setActive` is idempotent and never creates another RAF loop; inactive picking/focus returns `not-ready`. Abort rolls back view, bookmark, control/RAF state before the next request. Desk/table navigation never remounts the canvas. All methods after disposal return `disposed`; no RAF, listeners or async callback may revive it.
- Pointer methods use browser client CSS pixels, not device/backing-store pixels. Resize requires finite positive CSS dimensions and DPR. `project` returns null for a point not visible; `pickAt` returns none outside the map/canvas. Piece meshes are picked before the plane. Hits return the continuous ray/plane point in metres; no tile field is exposed. Map edges use inclusive metre bounds; test exact corners and off-map epsilon points. Clip generic ghosts, uncertainty graphics and labels to the map where appropriate; clipping never alters source position/appearance. Do not clamp an off-map hit into a valid selection. Shape offsets may be negative: transform them from the unit frame before bounds checks, never validate them as absolute map coordinates.
- Piece geometry uses supplied frontage/depth and arbitrary facing. Uncertainty is supplied knowledge, not a client rule for truth movement. A unit's display label is public name/estimate or a generic label, never an inferred enemy identity. Focus is explicit and never follows every view update.

**Continuous reconciliation:** HQ now consumes accepted #118 on main `af0dc698392f350b73cdfc3684e6adc3a1282ca0`. `ContinuousSurface` passes positions, dimensions, loose offsets and compass radians directly to `TableScene`; no tile conversion or facing quantization remains. The public preview is revision 2, 4000×3000 metres, registered to the whole 1200×900 image. The adapter passes an extent-only public `BaseMap` with no engine terrain features. Loaded-image validation and scene application share a commit boundary. CSS picking returns the continuous ray/plane coordinate, including piece hits; projection, bookmarks, resize and dolly offsets use metres. Saved revision-1 bookmarks do not match this artwork. CPU code gates do not replace actual browser/WebGL or performance acceptance.


### Fixture snapshot and HqDataSource

An instance is bound to one immutable `Scope`. Identity is assigned by fixture setup or authenticated transport; a client scope is not authorization. Switching game/side/player disposes the source/repository, aborts requests, clears selection and mounts a new scoped session. Shared public art can be cached independently; knowledge and local state cannot bleed across scopes.

Scope equality means **value equality of all three fields** `(gameId, sideId, playerId)`, never object identity, side alone or concatenated unescaped strings. Enforce it at source→snapshot, navigation→selection, surface→presentation→selection, repository→document→selection and all restore/async-result boundaries. Equal-valued independently allocated scopes are valid; a differing player on the same side is a mismatch. Camera restoration additionally matches map ID/revision.

`getState` is side-effect free. `subscribe` delivers the current state synchronously once and then ordered immutable states, with an idempotent unsubscribe. One failing listener must not prevent others receiving a state. `open` transitions idle→opening→ready/error; a second open while opening is `conflict`, while ready it returns the current snapshot. `refresh` replaces a full validated snapshot. Dispose aborts in-flight work, emits disposed once and clears listeners; subsequent reads show disposed and subscriptions deliver that final state once only.

Every snapshot carries a local epoch/ordinal observation token (gaps permitted); old-epoch results are discarded. **These do not assert a server sequence.** `authorityRevision=null` records the v1 gap. A disconnected source retains its last snapshot with stale=true, but freezes projected time and permits reading only. Retry is read-only. The fixture adapter never opens sockets, imports engine state, reads a log with truth or calls a model.

Reserve fixture refresh ordinals when requests start, not when their responses arrive. A newer accepted result makes an older in-flight result obsolete, even if its game time is equal or greater. Discard that completion/return `aborted`; it cannot get a freshly minted ordinal to bypass ordering. Validate nondecreasing game time within an epoch; replay seeking is outside this read-only source. The surface repeats these guards using presentation metadata. A v1 live stream still has no authoritative ordering proof.

Validate fixture SideViews with existing strict protocol schemas first, then semantic checks. Normalize only approved fields into the snapshot: unknown commander, per-field snapshot provenance, nullable unavailable observation times, supplied geometry and public confidence. Keep written/received dates distinct. In v1 `Dispatch.unit` is an untyped string: populate normalized `unitId` only when it exactly matches an approved own/public unit ID; otherwise leave null, without interpreting names as IDs. Optional absence becomes null/unknown, not an invented value.

Dispatch IDs are unique within scope. Identical repeats are no-ops; changed content under the same ID is a conflict requiring resync, not an extra paper/journal event. Sort by received game time, then ID. A time older than the last accepted snapshot cannot replace the current snapshot. Same-time ordering of v1 clock/barrier messages is unresolved; a future live adapter cannot prove consistency using local receipt order alone.

### Clock modes and barrier honesty

The read-only fixture clock includes mode, status, rate, authoritative time and barrier in one coherent fixture observation. A live v1 view cannot supply mode/revision coherence; label mode unknown and `coherence='unverified'`. `staffAtWork` can show a staff-working indicator, but a late `working=false` is not proof that a clock anchor is safe to extrapolate. Missing `needAtMs` is unknown, never zero.

Display advancement requires **all** of: source kind fixture; connection ready; stale=false; clock coherence fixture-atomic; status running; mode realtime; barrier clear. The canonical anchor is `snapshot.atGame = clock.authoritativeGameMs`, sampled with `receivedMonotonicMs` from that same accepted observation. Reject inconsistent anchors/nonfinite monotonic values/invalid rate. If a working barrier has a known need time, it cannot precede the authoritative time. Eligible display is `floor(authoritativeGameMs + max(0, nowMonotonicMs − receivedMonotonicMs) × rate)`, with safe-integer overflow rejected. Re-anchor from each accepted snapshot, never derive time from Date.now or server/client wall-anchor subtraction. Freeze at the last authoritative observation if any eligibility check fails. Fast-forward follows received progress; manual advances only through fixture inputs, not a UI ticker. A transition/resume re-anchors without accumulating paused/barrier duration. Do not invent an advance, pause vote or set-rate wire command.

Test rates 1/4/12/1000, all modes/statuses, disconnect/reconnect, negative monotonic deltas, barrier arrival/release and stale results. Fixture test time is injected; the engine never reads this display clock. A future live projection requires an accepted atomic mode/anchor/barrier/revision observation and freshness policy from the server owner, not just merging the existing separate messages.

### HqRepository and errors

The first `LocalDocument` persists **shell preferences only**: scope, schema version, revision, view, selection, camera and contrast/motion preference. Drafts, marks, read/file state and notes are intentionally not claimed by this version. Future additions require a separately reviewed schema/migration.

`load` creates/caches an empty/default v1 document with an opaque revision when storage is absent; repeated loads keep that revision until a save. Invalid or future-version data returns `invalid-data`/`migration-required` and is not overwritten. `save` requires `document.revision === expectedRevision === currentStoredRevision` (or the cached initial revision), validates scope/version and writes a replacement with a **new repository-generated** revision. The caller never generates the next revision. Success returns the saved document and actual durability. Failures before commit leave the last saved value unchanged. A single repository instance serializes saves. Browser storage does not guarantee atomic cross-tab compare-and-swap; this first gate requires one writer per scoped document, detects observed revision conflicts, and promises no cross-tab/browser/device synchronization. Multi-writer use must stay unavailable until a lock/transaction design is reviewed.

The browser save commit point is successful completion of the synchronous storage write. Check cancellation before that call: return `aborted` with no write. Once committed, return success with its revision even if abort fires immediately afterward; cancellation cannot undo persistence or report a committed save as failed. Disposal prevents later operations/callbacks but does not roll back a completed write. A session-memory save follows the same commit-point rule at assignment. Any future async repository must define its own equivalent commit semantics before substituting it.

Keys use an encoded tuple `(schema namespace, game, side, player)`, not delimiter concatenation that can collide. Saved selections/bookmarks are checked against the current source/map on restore. Mismatched bookmark revision is discarded; an unknown selected ID clears selection. Use browser persistence only for non-secret UI state. Storage denial/quota returns a visible error; the UI may explicitly choose a separate session-memory repository and must label that durability. Never silently call an unsaved value saved.

Ports return `Result`, not expected rejected promises. Programmer defects may throw and are caught at the application boundary. Errors contain safe text and retry guidance, never server stacks/payloads. Abort/dispose must stop listeners, loads and scheduled transitions; no stale completion can commit. `unsupported`/`scope-mismatch`/`unauthorized` never retry automatically; conflict needs resolution; reads can retry after offline/timeout. Future side-effect timeouts need `outcome-unknown`, not a promise that cancellation undid the server action.

Proposed first-gate adapter limits (UI validation, not server claims): safe integer game times/ordinals; finite geometry; map coordinates within supplied bounds; positive footprint/art extents; nonnegative age/radius; IDs ≤128 characters; labels ≤256; prose ≤16,384; ≤1000 pieces, ≤2000 papers and ≤256 shape points per piece. Reject unknown JSON fields at each imported/persisted boundary. Render all prose as text. Require `observedAtGame ≤ atGame`, `ageMs = atGame − observedAtGame` for stale contacts and `writtenAtGame ≤ receivedAtGame ≤ atGame` for fixture papers. These checks expose the existing contact-2 bug; zod alone does not.
