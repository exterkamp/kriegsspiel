# Owned battlefield geography library contract

Candidate implementation contract following the accepted lobby pairing design. This does not change native scenario approval or the existing guest lifetime/privacy policy. Independent acceptance is required before releasing the Add-map child.

Library port: client/src/shared/lobby-map-library/contracts.ts. Map summaries carry only library references, metadata, dimensions and SHA-256 full canonical asset identity; status is always needs-scenario, never native approval. Separate display name does not modify canonical asset bytes. Included and owned geography may be previewed; no arbitrary engine conversion or army/objective placement.

Storage/API: same caller-owned SQLite DatabaseSync/account lifecycle participants as creation receipts. Canonical bytes stored once per immutable owner operation, with immutable original-owner/request UUID and mutable current owner. Guest adoption transfers all owned assets and operation indexes atomically with auth/lobby/receipts; on key collision preserve both, owner/key lookup409, no third asset. Delete/expiry removes private canonical bytes and leaves inaccessible operation tombstones preventing reuse while retained; existing guest lifetime/privacy policy unchanged. Metadata display name160 nonblank, IDsUUID, identity64lowerhex. Owner-scoped list/read, 404 across ownership. No development sidecar, filesystem path input or production storage fallback.

Portable child presentation may use the frozen port after this contract is accepted; main live availability remains default-only until full chunk3 gates.

Durability capability: library save/add is advertised only with the task-owned durable SQLite owner (`DB_PATH`), never with an in-memory-only account store. No browser/localStorage/dev-sidecar persistence fallback. Main API can offer native default/curated play independently of this capability. The isolated durable preview will use a fresh task-owned database, preserving every protected database. Numeric ceilings are routine bounded-service choices, not a new account tier or change to guest expiration.

## R17 bounded corrections and frozen details

These replace any earlier aggregate-list or post-buffer admission reading above. Save quotas remain20 guest/100 account and128MiB/512MiB; retained adoption is never truncated. Listing is keyset-paginated at20 entries and32KiB UTF-8 per response, with an explicit nextCursor and no automatic aggregation. Port list(source, signal, cursor?) returns {items,nextCursor?}. Owned pages order by immutable createdAtMs descending then UUID descending; included pages order by immutable included ID ascending. All retained adopted entries remain reachable even above save quota. Cursors are at most512 ASCII characters, authenticated with a process-epoch HMAC bound to authenticated owner, source and immutable last key. Cursor payload contains ordering keys only, no other-owner identity. Reject invalid/foreign/old-epoch cursors with a readable restart-list400; client clears cursor on source/owner replacement and restarts paging explicitly. Never silently hide retained entries.

Admission is acquired in Fastify onRequest, before body parsing/accumulation or large SQLite reads: authenticate, check source/metadata/content-type, reject non-identity Content-Encoding, then reserve one shared global2/owner1 slot. Hold it through streaming receipt (separate30s deadline), validation (30s worker deadline), any readback, abort handling and awaited worker exit. Reject excess requests429 without application buffering or an unbounded queue. Count actual streamed bytes against64MiB independently of Content-Length and decode strict UTF-8. Reads and certification/reconciliation needing asset bytes use this same pool. Tiny metadata/receipt lookups do not acquire a large-asset slot until bytes/certification are needed. Query SQL byte length before retrieval and use CASE so oversized values never materialize in JavaScript. Client asset reads are also streamed and byte-bounded before decoding. Ordinary routes retain their small default body limit. Worker512MiB V8 ceiling bounds only that heap, not RSS/external buffers; no stronger memory guarantee is claimed.
